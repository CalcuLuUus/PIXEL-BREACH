# PIXEL//BREACH — 落日船坞

一个运行在桌面浏览器中的像素风 3D 第一人称射击 Demo。

玩家从落日船坞的入口堆场出发，穿过集装箱区与装卸平台，在开放船坞击败三阶段 Boss「零号守门者」，最后从码头尽头的出口撤离。

项目采用原生 HTML、CSS 和 JavaScript。场景、武器、敌人、灯光和表面纹理都在本地生成。默认使用 WebGL2 High，真实内部渲染尺寸为 `1920×1080`。

## 当前版本更新（V6 High Visual Overhaul）

V6 的目标不是单纯放大画布，而是让高分辨率真正服务于几何、材质、光影和战斗反馈。相较于 V5.1，当前工作区已经完成以下主要升级：

- 默认 High 路径改为 `1920×1080` WebGL2，保留既有 URL 画质参数作为兼容入口；
- 入口棚、集装箱区、装卸平台、轨道吊和维修龙门架重新组织，增加桁架、压槽钢板、角铸件、门锁杆、钢轨、轨枕、排水格栅、车辙、积水和磨损标线；
- 增加 `2048×2048` 方向光深度图，让场景结构、动态敌人和 Boss 能投射更明确的低角度夕阳阴影；
- 增加 HDR 场景颜色缓冲与离屏高光合成，灯具、核心、激光、枪口和曳光拥有清晰亮部与外部光晕；
- 表面纹理改为带 mipmap 的本地程序化纹理数组，进一步区分涂装钢板、铸件、混凝土、木材和橡胶；
- 重新设计脉冲步枪、裂能散射器、相位刃、漂移哨兵、双管炮台和零号守门者的结构层次；
- 保留既有两波敌人、500 HP Boss、150 HP 狂暴、跳跃、空中相位突进、换弹、补给点、出口、死亡/重试和暂停流程；
- 所有新增视觉资源继续由本地程序生成并在启动时预建，不引入 CDN、外部图片、模型、音频或运行时网络请求。

V6 的验证边界也明确记录在本文档中：当前已完成 JavaScript 语法、差异空白、离线 Chromium 流程和 WebGL 运行验证；SwiftShader 下的性能结果不能代表真实硬件 GPU。场景反射、折射、SSAO、MRT、全局光照和体积散射仍属于后续计划，而不是当前已经完成的功能。

## 游戏简介

**PIXEL//BREACH** 将像素化材质语言与户外落日港口结合起来：

- 内部渲染分辨率按画质为 `1920×1080`、`960×540` 或 `640×360`，始终为 16:9，再通过 CSS 适配显示尺寸；
- 场景为程序化户外船坞：集装箱、装卸平台、维修龙门架、轨道吊、叉车、系缆桩、护栏、水面与落日天空；
- 采用第一人称视角、鼠标转向和 Pointer Lock；
- 关卡线性推进：入口堆场 → 集装箱区 → 装卸平台 → 开放 Boss 船坞 → 撤离码头；
- 可步行区域约为旧室内场景的两倍；高分辨率保留像素刻字、扫描线和低多边形工业造型。

## 当前实现的功能

### 核心玩法

- 3D 第一人称移动、鼠标视角和 Pointer Lock；
- WASD 移动、`Shift` 冲刺和圆形碰撞限制；
- `Space` 跳跃：重力、落地检测、明确的可站立顶面白名单；
- 低集装箱、木箱、托盘和维修台阶可跳上或直接跨上，高层堆叠不可攀爬；
- 左键攻击、准星和命中反馈；
- 两波敌人后进入 Boss，Boss 击败后解锁出口；
- 靠近出口按 `E` 撤离；
- 受伤、死亡、重试、暂停和胜利流程。

### 跳跃与相位突进

- `Space` 仅在落地状态起跳，跳跃高度足以登上低箱，但不足以爬上 2 m 以上的集装箱堆；
- 可站立表面采用显式白名单，不依赖视觉模型自动推断；
- `Q` 相位突进仍提供短暂无敌，但不能穿过碰撞体；
- 空中每次跳跃只能使用一次空中突进，落地、死亡或重试后重置；
- 地面突进与空中突进共用冷却，HUD 显示冷却状态。

### 三种武器

1. **脉冲步枪**
   - 自动连射；
   - 30 发弹匣、120 发备用弹药；
   - Hitscan 远程攻击；
   - 换弹时间约 `1.25 s`。
2. **裂能散射器**
   - 单次发射五发散射弹；
   - 8 发弹匣、48 发备用弹药；
   - 近距离爆发伤害；
   - 换弹时间约 `1.1 s`。
3. **相位刃**
   - 无弹药限制；
   - 前方扇形近战攻击；
   - 约 `0.4 s` 的可见挥砍，命中窗口约 `0.10–0.23 s`；
   - 每次挥砍对同一目标最多结算一次，可击退敌人并处理附近的敌方子弹。

三把武器均有独立第一人称 ViewModel。步枪换弹包含枪身下压、弹匣脱落/回插和拉栓阶段；散射器换弹包含枪身倾斜、弹仓门开启、转鼓旋转和弹壳装填；相位刃有独立的挥砍姿态。弹药与伤害数值沿用原版本。

远程武器弹匣打空且仍有备弹时会自动换弹。HUD 显示 `RELOADING` 与装填进度百分比；相位刃不参与换弹。

### 角色技能

- `Shift`：普通冲刺；
- `Q`：相位突进，短时间快速移动并获得无敌效果，不能穿墙；
- `F`：过载脉冲，清除附近普通敌方子弹，对普通敌人造成伤害并减速，对 Boss 造成受限伤害；
- 技能具有冷却时间和 HUD 状态显示。

### 补给点

关卡中恰好有两个固定补给点：

- 入口堆场补给点；
- 装卸平台维修区补给点，位于 Boss 船坞之前，不在 Boss  arena 中心。

交互规则：

- 靠近后按住 `E` 约 `0.9 s`；
- 移动、松开 `E`、离开范围或跳起会中断；
- 补给过程中不能攻击，但受到的伤害仍然生效；
- 每个补给点独立冷却 `35 s`；
- 成功补给恢复 `+40 HP`、步枪备弹 `+50`、散射器备弹 `+16`，均按上限截断；
- 如果 HP 与两种远程备弹都已满，不会消耗冷却；
- HUD 面板显示 `READY`、`SUPPLYING`、`COOLDOWN` 或 `FULL`，场景灯具与地面环同步变色。

补给点的 `E` 交互与出口的 `E` 交互使用不同距离判定，不会互相覆盖。

### 敌人与 Boss

- 第一波：4 个漂移哨兵，从集装箱区进入；
- 第二波：4 个漂移哨兵与 2 个固定炮台，在装卸平台交火；
- Boss：零号守门者，最大 HP 为 **500**；
- Boss 阶段：
  - 第一阶段：`500–331 HP`，横向移动、直线能量弹和落点预警；
  - 第二阶段：`330–151 HP`，环形护盾、激光/屏障、核心暴露和增援；
  - 第三阶段：`≤150 HP`，进入 `ENRAGED`。

暴怒阶段只触发一次，包含红黑核心与装甲配色、HUD `ENRAGED`、红屏闪烁和一次径向弹幕爆发。暴怒后攻击间隔缩短约 25%、移动速度提高约 15–20%，并加入：

- 预警后的三向扇形弹幕；
- 2–3 枚有限存活时间的追踪弹；
- 两圈错位、带缺口的冲击波；
- 更短的核心暴露窗口。

Boss 不自我治疗，不会被单次伤害跳过阶段，也不会无限召唤；召唤受数量上限和冷却限制。Boss 死亡后出口保持原有的解锁与撤离流程。

### 视觉与技术（V6）

- **High 默认画质**以 `1920×1080` 在 WebGL2 上渲染，使用 16:9 画布。Balanced（`960×540`）和 Fallback（`640×360`）沿用原渲染路径。可用 `?quality=high`、`?quality=balanced` 或 `?quality=fallback` 选择。后端尺寸限制或 High 初始化失败时会降级。WebGL1 使用 Fallback，并根据片元 uniform 预算减少同时启用的灯光与材质选项。
- **太阳与阴影**使用程序化云层、地平线雾色和低角度太阳。2048×2048 方向光深度图覆盖可玩码头，静态遮挡预先缓存，哨兵、炮台和 Boss 的主要部件随游戏逐帧投影。地面保留固定池接触阴影。
- **表面与反光**使用两组带 mipmap 的共享纹理数组。每组包含 8 层 `256×256` 的程序化纹理，由颜色、法线扰动、粗糙度和 AO 区分涂装钢板、铸件、混凝土、木纹和橡胶。积水采用视角相关的天空反光，海面叠加动画波纹、太阳高光和岸边泡沫。
- **船坞结构**重新建模了带梯形压槽、角铸件与门锁杆的集装箱、入口横架、双桁架轨道吊和装卸平台维修龙门架。钢轨、轨枕、积水边缘、车辙、排水格栅和磨损标线贯穿步行区域。
- **武器与敌人**使用共享的倒角和锥形几何。High 为第一人称武器提供独立深度层和照明，保留装填部件的运动，并为哨兵、双管炮台和 Boss 增加可辨认的装甲与传感器。地面和标记过的障碍物会按钢材、混凝土或木材显示撞击反馈。
- **眩光**从离屏画面提取灯具、能量核心、曳光、枪口和激光的亮部，在 `480×270` 上分离模糊，再合成高光并进行色调映射。支持浮点颜色附件时，场景使用 `RGBA16F`，否则使用 `RGBA8`。
- 几何、纹理、着色器和帧缓冲均在启动时构建。武器、敌人、阴影槽和特效在游戏中复用固定资源。所有运行资源均由项目本地提供或生成。

### 渲染范围

阴影图覆盖码头可玩区域。水面与积水反射程序化天空，环境光遮蔽来自材质与接触阴影。当前渲染范围未包含场景反射、折射、SSAO、全局光照或体积散射。

## 安装与运行

### 环境要求

- 支持 WebGL 的现代桌面浏览器；
- Python 3，或者任意静态 HTTP 文件服务器；
- 不需要 `npm install`，也不需要下载额外依赖。

### 使用 Python 启动

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

然后在浏览器中打开：

```text
http://127.0.0.1:8000/
```

点击「开始突入」后，浏览器会请求锁定鼠标。首次进入时请允许 Pointer Lock，并确保浏览器启用了 WebGL / 硬件加速。

停止服务器：

```text
Ctrl+C
```

也可以使用任意静态文件服务器。建议通过 HTTP 运行，而不是直接双击 `index.html`。

## 本地验证

```bash
node --check game.js
node --check vendor/three.min.js
git diff --check
```

启动本地 HTTP 服务后，可直接用默认 High 画质运行：

```text
http://127.0.0.1:8000/
```

也可显式检查 High / Fallback：

```text
http://127.0.0.1:8000/?quality=high
http://127.0.0.1:8000/?quality=fallback
```

在浏览器控制台执行以下只读检查：

```js
window.__PB_RENDERING__.snapshot()
window.__PB_LIGHTING__.snapshot()
window.__PB_CINEMATIC_FX__.snapshot()
```

在 High 下，检查 `contextType === 'webgl2'`、`shaderVariant === 'high'`、`backbuffer` 为 `1920×1080`，以及 `features.realShadowMap`、`features.postProcessBloom` 和 `features.normalMapping`。`resources.sceneColorFormat` 报告实际离屏颜色格式。若发生降级，`profileReason` 会给出原因。

## 未来升级路线

未来升级以“先把高分辨率主路径做出质感，再考虑兼容与降级”为原则。重点不是继续单纯提高内部像素数量，而是让截图中能直接看到材质差异、阴影重量、环境反射、Boss 阶段变化和武器反馈。

### 第一阶段：材质与空间层次

- 建立更完整的材质参数：`albedo`、`normal`、`roughness`、`metalness`、`AO`、`emissive`、磨损和湿度；
- 让湿钢、涂装集装箱、锈蚀钢板、混凝土、木材、橡胶和积水拥有不同的光照反应；
- 增加 GTAO/SSAO 或稳定的高质量接触遮蔽，让集装箱底部、轮胎、平台连接处和 Boss 装甲缝隙真正落地；
- 优化级联阴影稳定性、近景阴影分配和阴影边缘柔化，避免相机移动时出现跳动；
- 增强前景地面的裂缝、伸缩缝、油污、轮胎擦痕、排水沟、检修盖和积水反射。

### 第二阶段：水面与环境反射

- 将船坞水面从程序化反光带升级为带法线扰动和 Fresnel 的环境反射；
- 反射天空、起重机、集装箱、激光、爆炸和 Boss 核心颜色；
- 区分远处海面、中景积水和近景浅水的反射清晰度；
- 增加子弹落水、脚步和爆炸造成的水花、波纹与反射闪烁；
- 让湿地面反射受裂缝、油污和水波打断，而不是形成整块镜面。

### 第三阶段：Boss、武器与命中特效

- 让 Boss 三个阶段拥有真正的机械形态变化：装甲闭合、核心环展开、散热片打开、过载装甲裂开；
- 让 Boss 狂暴状态同步改变舞台灯光、附近物体边缘光、地面红色反射、排气效果和体积雾；
- 继续细化三种第一人称武器的金属、橡胶、磨损、热量、后坐力和装填结构；
- 按 `steel`、`concrete`、`wood`、`water`、`enemyArmor`、`energyCore` 区分命中特效；
- 增加钢铁火花、混凝土粉尘、木屑、水花、能量碎片、弹痕和短暂局部破坏；
- 强化枪口、激光、相位刃和爆炸的“清晰核心 + 柔和光晕”层次。

### 第四阶段：体积光、色彩与场景叙事

- 增加克制的夕阳光束、集装箱走廊阴影雾、远处海雾和 Boss 狂暴红色能量雾；
- 完善 Filmic/ACES 色调映射、暖色高光、蓝紫阴影、曝光、暗角和抗锯齿；
- 用区域灯光变化表现敌人出现、Boss 入场、Boss 狂暴和 Boss 死亡后的出口解锁；
- 增加起重机、警报灯、远处机械和战斗反馈音效；
- 增加开场、Boss 入场、狂暴和撤离等短镜头，让关卡视觉变化与玩法阶段同步。

### 第五阶段：内容与验证

- 增加更多港口区域、敌人类型和 Boss 攻击组合；
- 增加可破坏的小型工业道具、弹痕和环境状态变化；
- 增加固定相机、固定时间、固定种子的 V5.1/V6/A-B 截图流程；
- 以“关闭调试信息后，肉眼能否判断新版明显更好”为视觉验收标准；
- 在视觉主路径稳定后，再进行真实设备性能测试、浏览器兼容性和低性能模式设计；
- 增加键位自定义、音量、画面效果设置和完整的性能档位。

暂不以继续提高到 2K/4K、增加随机噪声、堆叠不可见的 Shader 参数或过度依赖色差/扫描线作为主要升级方向。优先保证几何轮廓、材质反应、阴影重量、反射层次、Boss 形态和战斗反馈在截图中清晰可见。

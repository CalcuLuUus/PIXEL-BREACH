## 一、项目目标

将当前 PIXEL//BREACH 从“像素化程序化工业风”直接升级为最终版 **V7 Realistic Dockyard**：

> **写实工业港口 + 电影化夕阳光照 + 平滑高分辨率材质 + 科幻战斗反馈**

V7 的重点不是单纯提高内部渲染分辨率，而是让分辨率真正服务于：

- 真实比例的工业几何；
- 可区分的金属、混凝土、木材、橡胶、玻璃和水面材质；
- 有重量的动态阴影和接触遮蔽；
- 湿地面、积水和金属的受控反射；
- 具有结构层次的武器、敌人和 Boss；
- 清晰、克制、与材质相关的战斗特效；
- 平滑而非像素化的 HUD 与整体界面。

不再设计任何中间版本或分阶段发布版本。所有实现工作都服务于一个目标：**在当前仓库内完成可运行、可验证、离线的最终 V7。**

## 三、当前画面为什么仍然像素化

即使当前 High 路径已经是 `1920×1080`，画面仍然明显像素化，原因不只是内部渲染分辨率：

1. `vendor/three.min.js` 是项目自带的精简兼容渲染层，当前没有完整现代 PBR 工作流。
2. 材质主要依赖 `MeshLambertMaterial`、`MeshBasicMaterial` 和自定义近似参数，真实金属、粗糙度、法线层次不足。
3. 表面纹理主要来自程序化的 `256×256` 层和世界空间细节，结构仍然偏“像素纹理”。
4. 环境几何大量由低多边形程序化盒状结构组成。
5. 反射主要是伪反射条带，而不是真正的环境反射。
6. `style.css:179` 附近仍有像素化画布展示逻辑。
7. `style.css:195` 附近仍有扫描线层。
8. `style.css:46` 使用了 `-webkit-font-smoothing: none`。
9. `game.js:384` 附近的工业材质和 `game.js:844` 附近的表面纹理系统主要是为了像素工业风设计，而不是为了写实材质。

因此，不能只修改：

```css
image-rendering: pixelated;
```

必须同时升级渲染基础、资产、材质、光照、场景几何、角色、武器、特效和界面。

- 低角度夕阳、蓝紫色阴影和港口雾气；

### 4.2 风格边界

以下是实现要求，不是可选建议。implementer agent 应根据仓库实际情况落地；如果完整方案与当前兼容渲染层冲突，应优先保证最终画面和离线运行，再采用能达到同等效果的本地实现。

### 5.1 先建立 V6 基线，但不要发布中间版本

在开始视觉修改前，固定当前实现的可比较基准：

1. 固定场景截图位置：
   - 入口棚；
   - 集装箱区；
   - 装卸平台；
   - Boss 船坞；
   - Boss 狂暴阶段；
   - 出口解锁阶段。
2. 固定测试状态：
   - 固定随机种子；
   - 固定时间和天气；
   - 固定相机位置；
   - 固定敌人和 Boss 状态。
3. 记录当前指标：
   - 内部渲染尺寸；
   - FPS 或帧时间；
   - draw calls；
   - 三角形数量；
   - 活跃灯光；
   - 阴影数量；
   - 纹理数量和内存；
   - 特效池使用率。
4. 现有渲染路径可以保留为开发对照，但最终默认启动效果必须是 V7 写实路径。

不要把基线工作做成用户可见的小版本，也不要新增 V7.0/V7.1 之类版本分支。

### 5.2 渲染层和加载方式

当前 `game.js:127` 至 `game.js:256` 负责画质选择和后端降级。应在不破坏已有入口的前提下重构渲染基础：

1. 优先使用功能完整的本地 WebGL2 渲染路径。
2. 如果扩展 `vendor/three.min.js`，必须确保实际支持以下能力，不能只在诊断接口中伪造字段：
   - 标准 PBR 材质；
   - sRGB 纹理和输出；
   - 线性空间光照；
   - mipmap 和各向异性过滤；
   - 阴影贴图；
   - framebuffer / render target；
   - 法线、粗糙度、金属度和 AO 采样；
   - 后处理所需的全屏合成；
   - WebGL2 texture、float color attachment 或可靠的 RGBA8 fallback。
3. 如果引入完整本地渲染库，文件必须放进 `vendor/`，不能使用 CDN，不能要求 npm install 才能运行。
4. 保持 `index.html` 通过本地脚本或本地 module 加载。
5. 保持 WebGL1/Fallback 能够进入游戏，但 Fallback 可以关闭复杂 PBR、反射、后处理和高质量阴影；Fallback 仍应是平滑画面，不得主动使用像素化缩放。
6. 渲染器初始化失败时必须显示现有 fatal UI，而不是静默白屏。
7. `window.__PB_RENDERING__.snapshot()` 必须报告真实状态，包括：
   - 实际 context 类型；
   - 实际画质；
   - 实际内部尺寸；
   - 实际材质路径；
   - 实际阴影和后处理是否启用；
   - 实际是否降级及原因。

### 5.3 平滑高分辨率显示

必须彻底移除明显的像素化表现：

1. 修改 `style.css:179` 附近的画布展示规则：
   - High、Balanced、Fallback 均使用平滑采样；
   - 不再使用 `image-rendering: pixelated` 或 nearest-neighbor 作为视觉默认；
   - 可以为兼容性保留普通 `image-rendering: auto`。
2. 删除或大幅减弱 `style.css:195` 附近的扫描线层。
3. 删除 `style.css:46` 的 `-webkit-font-smoothing: none`，改为平滑字体显示。
4. 删除或重做所有强制 nearest-neighbor 的 CSS 和渲染分支。
5. 画布应支持真实抗锯齿方案：
   - 优先使用 WebGL2 + TAA 或 MSAA 能力；
   - 不可用时使用 FXAA 或可靠的后处理抗锯齿；
   - 不得通过低分辨率放大模拟像素风。
6. 画布始终保持 16:9，但可以通过内部 render scale 控制性能。

推荐最终画质含义：

| 档位 | 初始内部尺寸 | 视觉目标 |
|---|---:|---|
| High | 1920×1080 或根据窗口/GPU动态调整 | 完整写实材质、动态阴影、主要反射、AO、Bloom |
| Balanced | 1600×900 或 1280×720 | 写实材质、标准阴影、简化反射和后处理 |
| Fallback | 960×540 | 平滑材质和基础光照，关闭复杂反射和高成本后处理 |

不必机械地固定尺寸，必须优先保证窗口比例、设备能力和稳定帧时间。

### 5.4 动态分辨率和性能控制

实现动态 render scale，而不是直接退回像素画面：

- 目标帧时间：约 16.6 ms；
- 连续超过约 20 ms 时逐步降低 render scale；
- 连续低于约 13 ms 时逐步提高 render scale；
- 设置上下限，避免频繁抖动；
- 对画质变化做平滑过渡；
- 诊断接口报告目标帧时间、当前 render scale、最近帧时间和是否发生动态降级。

建议初始范围：

```text
High：0.75–1.00
Balanced：0.65–0.90
Fallback：0.50–0.75
```

实际范围应依据浏览器和真实设备测试调整。不能为了达成 FPS 把画面降成明显像素化。

### 5.5 色彩管理和色调映射

实现完整的颜色管理：

- Base Color 纹理按 sRGB 读取；
- 光照计算在线性空间进行；
- 发光和光源使用 HDR 数值或等价的线性强度；
- 输出转换为 sRGB；
- 使用 ACES、AgX 或 Filmic 类色调映射；
- 支持曝光控制；
- 高光不应全部剪裁成白色；
- 暗部应保持层次，不得整体发灰。

V7 的暖色夕阳、蓝紫阴影、青色能量和红色狂暴效果必须通过色彩管理统一，而不是各个材质单独使用未经管理的纯色。

- 锈蚀钢；
- 铸铁；
- 混凝土；

- 玻璃；
- 水面；

资源要求：

- 重要近景材质可以 2K；
- 4K 只给确实需要的 Boss、武器或近景资产；

- 远景使用低分辨率或简化材质；

### 5.10 环境反射和水面

当前 V6 的伪反射条带不能作为 V7 High 的主要反射方案。需要按成本实现真实或等价的环境反射。

#### 水面

- 使用 planar reflection、受控反射纹理或等价方案；
- 使用 Fresnel；
- 使用法线扰动；
- 根据距离降低反射清晰度；
- 反射天空、起重机、集装箱、激光和 Boss 能量颜色；
- 加入动画波纹、岸边泡沫和战斗水花；
- 不实现昂贵且不稳定的全场实时反射；
- 反射失败时回退到天空色和高光，不得变成黑洞。

#### 湿地面和积水

- 通过 roughness 和 wetness mask 控制反射强度；
- 用裂缝、油污和水波打断整块镜面；
- 近景浅水反射比远景海面清晰；
- 允许能量攻击在地面反射中留下短暂颜色；
- 不要让所有沥青地面都像镜子。

#### 金属

- 使用本地 HDR 环境贴图或等价天空环境；
- 通过 roughness 区分涂装钢板、抛光边缘和锈蚀区域；
- 只在必要区域使用高质量反射。

### 5.11 后处理

使用克制的后处理组合：

- TAA、FXAA 或等价抗锯齿；
- GTAO / SSAO 或稳定的接触遮蔽；
- Bloom；
- Filmic/ACES/AgX 色调映射；
- 曝光；
- 轻微雾气和体积光；
- 只在菜单或演出镜头使用非常克制的景深。

必须删除或明显弱化：

- 扫描线；
- 强色差；
- 强烈暗角；
- 过度 Bloom；
- 人工像素噪声；
- 用后处理掩盖低质量几何。

后处理必须有质量开关，并且在 Fallback 关闭高成本功能时仍然输出正常画面。

### 5.13 敌人和 Boss

#### 漂移哨兵和炮台

- 炮台枪管、底座和旋转结构实际运动；
- 低血量时显示热量、故障或受损状态；
- 保留现有实体池和战斗数值。

#### 零号守门者

Boss 是 V7 最重要的视觉对象，三阶段必须有真实形态变化，而不是只换颜色。

第一阶段：

- 装甲闭合；
- 粉色核心；
- 稳定能量环；

## 六、最终质量档位

V7 的 High、Balanced、Fallback 都应是同一套写实风格的不同成本，不得再把低档位做成像素版：

| 档位 | 材质 | 阴影 | 反射 | 后处理 | 目标 |
|---|---|---|---|---|---|
| High | 1K–2K PBR，重要对象更高 | 稳定动态阴影 + 接触阴影 | 水面和局部环境反射 | AO + Bloom + 抗锯齿 + 色调映射 | 默认桌面体验 |
| Balanced | 1K PBR | 简化动态阴影 | 简化水面反射 | FXAA/基础 AO + Bloom | 普通设备 |
| Fallback | 512–1K 或程序化平滑材质 | 基础阴影/接触遮蔽 | 关闭复杂反射 | 基础色调映射 | 兼容模式 |

所有档位都必须满足：

- 平滑边缘；
- 正常抗锯齿或可靠替代；
- 正确的材质颜色；
- 不使用像素化 CSS；
- 不使用扫描线模拟细节；
- 不因画质降级而改变玩法数值。

## 七、性能预算

写实画面不能以不可运行作为代价。implementer agent 必须保留真实设备上的性能可测性。

High 的建议目标：

- 1920×1080 起始内部尺寸；
- 高端桌面设备目标 60 FPS；
- 单帧预算约 16.6 ms；
- 战斗过程中不创建新的 Mesh、Geometry、Material、Texture；
- 可见场景使用 LOD 和实例化；
- 静态物体尽量合批；
- 动态灯光有限；
- 特效对象池有固定上限；
- 纹理通过 mipmap、复用和按距离降级控制内存。

建议初始预算：

```text
可见三角形：500K–1.5M
实时局部灯光：8–16
阴影投射灯光：1 个太阳 + 少量关键灯
高质量阴影贴图：2048 或稳定分区 2048
近景纹理：2K 为主，4K 只给重要对象
战斗粒子：不超过现有对象池容量的约 1.5 倍
```

实际预算必须在至少一台真实 WebGL2 GPU 和一条 Fallback 设备上验证。不能只在 SwiftShader 上判断是否完成。

- 是否有模型/纹理/字体路径在本地不存在？
- 是否有大小写路径问题？
- 是否能通过 Python 静态 HTTP 服务直接启动？
- 是否正确保留 `vendor/` 和本地依赖？
- README 是否准确描述已完成内容，没有把未来计划写成已实现？
- 是否误提交临时截图、缓存、构建产物或过大的调试文件？
- 是否出现未处理的 console error、404、shader error 或资源加载异常？

## 10.6 诊断接口真实性

- `window.__PB_RENDERING__.snapshot()` 的 context、backbuffer、quality、features 和 resources 是否真实？
- `window.__PB_LIGHTING__.snapshot()` 是否反映真实活跃灯光和阴影状态？
- `window.__PB_CINEMATIC_FX__.snapshot()` 的池容量、活跃对象和特效数量是否与实际一致？
- 是否通过把字段固定为 `true` 来伪造 normal mapping、Bloom、SSR、SSAO、HDR 或 reflection？
- 如果某功能因 GPU 不支持而降级，snapshot 是否明确报告原因？

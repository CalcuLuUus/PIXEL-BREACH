# PIXEL//BREACH V8：3A 级电影化船坞升级计划

> **目标版本：V8**  
> **文档用途：提供给 implementer agent 执行，并提供给 reviewer agent 作为完整验收标准。**  
> **视觉目标：原创的 3A 级写实工业港口体验，接近现代开放世界动作游戏的电影化表现。**

---

## 0. 重要定位与范围

V8 不是简单的 V7 材质增强，也不是继续堆叠 Bloom、贴图和后处理。V8 的目标是从各个方面把 PIXEL//BREACH 升级为一款具有 **3A 级视觉完成度、电影化叙事、可信世界结构、现代战斗反馈和稳定运行能力** 的原创浏览器游戏。

可以参考现代开放世界游戏所具备的以下品质：

- 真实比例和可信尺度；
- 高质量 PBR 材质；
- 稳定的昼夜、天气、雾和反射；
- 详细的角色、武器和载具；
- 自然的动画和摄像机语言；
- 环境叙事和动态世界状态；
- 电影化任务流程；
- 统一的声音、音乐和 UI；
- 稳定的性能、资源流送和画质档位。

但 V8 **不得复制 GTA5 的角色、地图、任务、车辆、UI、音乐、美术资产、标志、镜头、对白或具体场景**。GTA5 只能作为“开放世界 3A 级完成度”的广义参考，V8 必须保持 PIXEL//BREACH 自己的原创身份：

> **落日船坞、工业科幻、断层突围、机械 Boss、能量武器和高密度港口叙事。**

由于本项目目前是原生 HTML/CSS/JavaScript + 本地 WebGL 的离线浏览器项目，V8 的目标应定义为：

> **在浏览器约束内实现 3A 风格的关键视觉和交互品质，而不是宣称具备主机/大型商业游戏的完整规模。**

任何无法在浏览器中稳定实现的高成本功能，都必须有清晰的降级方案，而不是通过诊断接口伪造已完成。

# 一、V8 最终目标

## 1.1 视觉目标

V8 最终应呈现：

- 真实的落日港口空间；
- 具有尺度感的集装箱堆场、起重机、船坞、维修区和海面；
- 高质量金属、混凝土、沥青、锈蚀、玻璃、橡胶、木材和水面材质；
- 稳定的太阳阴影、环境遮蔽、接触阴影和局部光照；
- 真实的湿地面、积水、雾气、反射和夕阳散射；
- 高质量武器 ViewModel、敌人、炮台和 Boss；
- 可信的机械动画、受击反馈和销毁演出；
- 清晰且克制的电影化色彩，不依赖像素化、扫描线或过度色差；
- 近景可观察细节，中景结构清晰，远景具有空间层次。

## 1.2 玩法目标

保留现有第一人称战斗核心，同时扩展为更完整的任务体验：

- 入口、集装箱区、装卸平台、开放船坞和撤离码头形成连贯空间；
- 战斗区域之间存在有意义的穿越、侦察、补给和选择；
- 敌人拥有更清晰的行为层级、警戒状态、掩体使用和协同；
- Boss 战具有入场、阶段切换、环境变化和死亡演出；
- 玩家移动、跳跃、冲刺、相位突进和近战攻击具有更自然的反馈；
- 任务目标、警报、敌人增援、撤离和环境状态都能被玩家理解；
- 关卡不因视觉升级而牺牲可读性和战斗公平性。

## 1.3 技术目标

- 默认使用本地 WebGL2 高质量路径；
- 可选支持 WebGPU，但 WebGPU 不能成为唯一运行前提；
- 所有运行资源本地提供；
- 支持静态 HTTP 直接运行；
- 支持 High、Balanced、Fallback 三个写实画质档位；
- 支持动态分辨率、LOD、对象池、纹理缓存和资源流送；
- 高档位以 1080p/60 FPS 为目标，实际性能必须在真实 GPU 上验证；
- 低档位仍然是平滑写实画面，不退回明显像素风；
- 诊断接口真实反映渲染器、资源、性能和降级状态。

# 二、现状审计与 V8 原则

## 2.1 当前项目的基础

当前项目已经具备：

- 第一人称玩家控制；
- Pointer Lock 和鼠标视角；
- 跳跃、冲刺、相位突进和过载脉冲；
- 三种武器和换弹逻辑；
- 两波敌人、炮台和三阶段 Boss；
- 补给点、出口、暂停、死亡和结算；
- 程序化工业船坞；
- V6 High/Balanced/Fallback 渲染入口；
- 方向光阴影、程序化材质、粒子、曳光、激光、冲击波和对象池；
- `window.__PB_RENDERING__`、`window.__PB_LIGHTING__` 和 `window.__PB_CINEMATIC_FX__` 诊断接口。

这些玩法和流程是 V8 的基础，不应被视觉重构随意破坏。

## 2.2 当前架构的主要限制

V8 实现前必须承认以下限制：

1. `game.js` 规模已经很大，玩法、场景、渲染、特效和 UI 职责耦合严重。
2. 当前自带 `vendor/three.min.js` 是兼容性渲染子集，不等价于完整现代 3D 引擎能力。
3. 当前场景仍然高度依赖程序化盒状几何，近景真实细节不足。
4. 当前材质存在 PBR 近似，但完整的纹理、法线、粗糙度、AO、环境反射和颜色管理仍需系统化。
5. 当前反射、体积光和接触遮蔽存在程序化近似，距离 3A 级稳定效果仍有差距。
6. 当前角色和 Boss 的结构、动画和受损状态仍然偏 Demo 级。
7. 当前没有完整的音频、动画状态机、资源导入、LOD、场景流送和存档设置系统。
8. 单文件开发方式不适合继续无边界扩张。

## 2.3 V8 总原则

- **先架构，再堆资产。**
- **先稳定可见的近景质量，再增加远景规模。**
- **先保证光照、材质、阴影和动画的统一，再加入昂贵特效。**
- **所有 3A 感必须来自可验证的几何、材质、光照、动画、声音和镜头，不允许只靠后处理伪装。**
- **不改变现有战斗数值，除非明确记录为设计变更并有玩法验证。**
- **每个高成本效果必须有 High/Balanced/Fallback 三级方案。**
- **必须支持真实浏览器和真实 GPU 验证。**
- **不依赖外部网络。**

# 四、3A 级渲染和画面升级

## 4.1 渲染基础

V8 需要将当前渲染器提升为真实的现代 WebGL2 渲染路径：

- PBR 标准材质或等价实现；
- 线性空间光照；
- sRGB 输入和输出；
- HDR 或高精度颜色缓冲；
- 稳定的 render target；
- 深度纹理和阴影贴图；
- 法线、粗糙度、金属度和 AO；
- mipmap、各向异性过滤和纹理压缩的可选支持；
- 全屏后处理；
- TAA、FXAA 或 MSAA；
- 稳定的色调映射和曝光控制。

如果当前本地渲染子集无法真实支持这些功能，应：

1. 扩展渲染层；或
2. 引入固定版本的完整本地渲染库；或
3. 在仓库内实现足够的 V8 专用渲染路径。

不能只在 snapshot 中宣称支持 PBR、HDR、Bloom 或阴影，而实际 shader 没有使用这些功能。

## 4.2 画质档位

| 档位 | 目标 | 材质 | 阴影 | 反射 | 后处理 |
|---|---|---|---|---|---|
| Ultra/High | 1080p/60 FPS 优先 | 1K–2K PBR，重要对象可更高 | 2048 级太阳阴影 + 动态接触阴影 | 水面、局部湿地面和环境近似反射 | TAA/FXAA、AO、Bloom、色调映射、雾 |
| Balanced | 普通桌面设备 | 1K PBR 和共享材质 | 1024–2048 简化阴影 | 水面简化反射 | FXAA、基础 AO、Bloom |
| Fallback | 兼容运行 | 512–1K 平滑材质 | 基础太阳/接触阴影 | 关闭昂贵反射 | 基础色调映射和雾 |

所有档位都必须：

- 平滑显示；
- 不使用 `image-rendering: pixelated`；
- 不使用扫描线作为主要画面处理；
- 不因降级而改变玩法；
- 在资源加载失败时显示可见 fallback。

## 4.3 动态分辨率

实现稳定的动态分辨率：

- 目标帧时间 16.6 ms；
- 使用滑动平均而不是单帧判断；
- 低于目标持续一段时间后提升分辨率；
- 高于目标持续一段时间后降低分辨率；
- 使用滞回避免频繁抖动；
- 视角快速转动和战斗特效高峰时允许短暂降级；
- UI 和 HUD 不跟随内部 3D render scale 变模糊；
- snapshot 报告当前 scale、目标帧时间、平均帧时间和最近峰值。

## 4.4 色彩、曝光和电影化调色

实现：

- Base Color sRGB；
- 光照线性计算；
- HDR 发光和灯光；
- ACES、AgX 或 Filmic 色调映射；
- 曝光自动或区域控制；
- 蓝紫阴影、橙色夕阳、青色能量和红色狂暴统一调色；
- 高亮区域避免一片纯白；
- 暗部保留材质层次；
- 不使用强烈色差替代真实光照。

## 4.5 环境光、太阳和天空

建立完整的外部环境光照：

```text
低角度太阳
+ 天空环境光
+ 地平线散射
+ 局部灯光
+ 接触阴影
+ 区域雾
+ 湿表面反射
```

实现：

- 太阳盘和太阳方向；
- 程序化或本地 HDR 天空；
- 夕阳云层；
- 地平线颜色渐变；
- 远处海雾；
- 近景雾层；
- Boss 区域的灯光和雾气变化；
- 出口解锁后的环境色变化。

## 4.6 阴影和遮蔽

必须重点提升空间重量：

- 太阳方向光阴影；
- 集装箱堆叠阴影；
- 起重机和龙门架阴影；
- 角色脚下接触阴影；
- 物件底部 AO；
- Boss 装甲缝隙阴影；
- 护栏、钢轨和平台连接处阴影；
- 动态敌人和炮台阴影；
- 阴影稳定性，避免相机移动跳动；
- High 使用更高分辨率或分区阴影，低档位使用简化阴影。

## 4.7 环境反射和水面

水面应成为 V8 的关键镜头元素：

- Fresnel；
- 视角相关反射；
- 法线扰动；
- 夕阳高光；
- 起重机和天空的近似反射；
- Boss 红色能量和激光的局部颜色反射；
- 岸边泡沫；
- 子弹和爆炸水花；
- 波纹对象池；
- 远近不同的反射清晰度。

湿地面应具备：

- wetness mask；
- roughness 变化；
- 油污打断反射；
- 裂缝打断反射；
- 局部积水；
- 能量攻击留下的短暂颜色残留。

不得让整个地面变成镜面，也不得在反射失败时出现黑色方块。

## 4.8 后处理

建议组合：

- TAA 或 FXAA；
- GTAO/SSAO 或稳定的屏幕空间接触遮蔽；
- Bloom；
- Filmic/ACES/AgX；
- 雾和轻度体积光；
- 轻微镜头曝光变化；
- 仅在菜单或 Boss 演出使用克制景深；
- 轻度运动模糊仅在冲刺/相位突进中使用，并可关闭。

必须避免：

- 强扫描线；
- 强色差；
- 过度 Bloom；
- 过度暗角；
- 低分辨率噪声；
- 依赖后处理掩盖低面数或低质量材质。

# 五、3A 级世界和场景升级

## 5.1 世界布局

把当前线性场景升级为一个具有“可回看、可穿越、可观察”的小型港口世界：

```text
入口安检区
  ↓
集装箱堆场
  ├── 侧向维修通道
  ├── 高处观察平台
  └── 补给和掩体区域
  ↓
装卸平台
  ├── 轨道与起重机下方
  ├── 维修龙门架
  └── 船坞边缘
  ↓
开放 Boss 船坞
  ├── 中央战斗区
  ├── 周边掩体
  ├── 能量设施
  └── 出口码头
```

不必做到大型开放世界面积，但应做到：

- 远景能看到区域之间的关系；
- 玩家能理解自己在港口中的位置；
- 入口、战斗区、补给点和出口具有明确地标；
- 场景不仅是敌人刷新的盒子集合；
- 动线、视线、掩体和高低差服务玩法。

## 5.2 模块化资产套件

建立模块化港口资产：

- 地面模块；
- 混凝土平台；
- 沥青路面；
- 轨道；
- 排水沟；
- 护栏；
- 楼梯；
- 维修梯；
- 集装箱；
- 起重机桁架；
- 龙门架；
- 灯杆；
- 电缆；
- 管道；
- 维修设备；
- 工业标识；
- 安全线和警示贴花。

通过拼接、变体、颜色和贴花形成自然差异，避免每个物体都复制粘贴。

## 5.3 集装箱

集装箱必须从简单盒子升级为可信工业资产：

- 波纹钢板；
- 角铸件；
- 门板；
- 门锁杆；
- 铰链；
- 编号和运输标识；
- 不同涂装；
- 褪色；
- 锈蚀；
- 凹陷；
- 划痕；
- 底部尘土和湿气；
- 可见堆叠接触关系。

模型要求：

- 近景完整模型；
- 中景低模；
- 远景实例化或简化模型；
- 视觉模型和碰撞盒分离；
- 集装箱在高处、通道和战斗掩体中的摆放有设计目的。

## 5.4 地面、道路和船坞边缘

地面是写实感的核心，必须包含：

- 沥青和混凝土材质混合；
- 伸缩缝；
- 裂缝；
- 轮胎痕迹；
- 油污；
- 水洼；
- 排水沟；
- 检修盖；
- 钢轨和轨枕；
- 黄色安全线；
- 褪色标线；
- 弹痕和战斗破坏；
- Boss 战后的烧蚀区域；
- 岸边泡沫和湿痕。

使用 PBR 材质、贴花、顶点色、mask 和少量真实几何组合，避免所有细节都变成独立 Mesh。

## 5.5 起重机、龙门架和机械设备

近景结构应包含：

- 真实钢梁截面；

# 十四、性能、内存和浏览器约束

## 14.1 性能目标

High 的目标：

- 1920×1080；
- 真实 WebGL2 GPU 目标 60 FPS；
- 高峰帧时间尽量不超过 25 ms；
- 战斗时不出现明显卡顿；
- 不出现持续内存增长；
- 不在帧循环创建大型对象。

建议预算：

```text
可见三角形：500K–2M，按 LOD 控制
实时局部灯光：8–16
太阳阴影：1 个主要方向光
关键动态投影灯：有限且按距离启用
阴影贴图：1024–2048，High 可使用分区策略
近景纹理：1K–2K 为主
重要对象纹理：最多少量 4K
战斗粒子：固定池
持久 Decal：固定上限
反射更新：按区域、距离和帧率节流
```

## 14.2 内存管理

必须做到：

- 纹理缓存；
- 模型缓存；
- 材质缓存；
- 音频缓存；
- 可控释放；
- 不重复加载；
- 重试后无泄漏；
- 关闭区域时释放非必要资源；
- 不 dispose 仍被其他对象使用的共享资源；
- 诊断接口提供近似资源计数。

## 14.3 帧循环规则

帧循环中禁止：

- 每帧 new Mesh；
- 每帧 new Geometry；
- 每帧 new Material；
- 每帧 new Texture；
- 无限 push 数组；
- 无上限创建粒子、Decal、音频节点；
- 反射或阴影导致无条件多次全场景渲染。

临时数学对象应复用，或使用明确的临时对象池。

## 14.4 浏览器兼容

至少验证：

- Chromium/Chrome WebGL2；
- Firefox WebGL2；
- Safari 或 WebKit 的降级路径（如果环境可用）；
- WebGL1/Fallback；
- WebGL context lost；
- 窗口改变；
- Pointer Lock 失败；
- 音频未解锁；
- 页面切后台和恢复。

# 二十、最终原则

V8 不是把 PIXEL//BREACH 变成 GTA5 的复制品，而是把它升级为：

> **拥有现代 3A 级写实材质、电影化光照、可信工业世界、完整声音和动画、成熟战斗反馈的原创科幻港口游戏。**

最终评价标准不是代码增加了多少，也不是加入了多少后处理，而是玩家在关闭调试信息后，能否明显感受到：

- 场景有真实尺度；
- 材质有真实反应；
- 阴影有重量；
- 水和湿地面有层次；
- 角色和 Boss 有结构；
- 武器有机械感；
- 战斗有声音和反馈；
- 任务有节奏；
- 世界有叙事；
- UI、音频、镜头和玩法属于同一个完整产品。

**让高分辨率、PBR、动画、声音、任务和系统架构共同服务于可信的 3A 级原创体验，而不是用单一特效伪装完成度。**
